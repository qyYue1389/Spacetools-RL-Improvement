# P6 manual classification

| Content | Description |
|---|---|
| `pending31.json` | The 31 items that still need a look at the image after criteria A/B/C (generated by: `--dump-cases` of `tools/p6/p6_relations.py`, plus the "detection does not match" items and the remainder) |
| `verdicts.jsonl` | Per-item conclusions and **evidence** for 32 items (generated by: `tools/p6/verdicts.py`) |
| `cards/` | 32 review cards: original image + the point the tool actually returned + question text/GT/model answer/criterion/distance |

The cards can be regenerated; this needs the `eval-benchmarks` parquet files and `pandas`/`pyarrow`/`PIL`:

    python3 tools/p6/make_cards.py --data <path>/eval-benchmarks/data

## Two things that must be stated

**There is only one round of annotation, so κ cannot be computed.** These 31 items are single-annotated (no second annotator),
so there is **no inter-annotator agreement measure**. The mitigation is to publish the per-item evidence in `verdicts.jsonl`
— each item states "on what grounds" — so others can check the conclusions without having to trust the annotator.
To report κ, a second person would need to label the same batch independently.

**The point on the card is the point the tool** actually **returned**, not the GT, and not the model answer.
Judging "tool error" means looking at which object this point lands on.
