## 0. Conclusion in one sentence

**GFlowRL itself still has no public implementation, but its direct predecessor FlowRL does, built on verl,
license Apache-2.0 — that is exactly the 90% of the pipeline we need.**
Even better: FlowRL needs three files changed, two of which **exist only to house the `Z_φ` network**,
and that is precisely what GFlowRL deletes. **Our change is smaller than FlowRL's.**

| Repo | What it is | What we can borrow | license / size |

| `microsoft/gflowrl` | The official implementation the paper claims | **Still 404** (reconfirmed 2026-09-01) | — |

The latter is consistent with the paper's own Appendix A sentence "unclear whether ... extends to broader agentic or
multimodal RL settings" — **A′'s gap is still empty.**

## 1. FlowRL: the one most worth copying

`https://github.com/Xuekai-Zhu/FlowRL` · Apache-2.0 · built on **verl**
(the README gives two paths: verl 0.4.0 to reproduce the paper, or hook into the latest verl).
The repo ships a **`FLOWRL_SIMPLE_GUIDE.md`** that directly gives the files to change and the code.

### 1.1 Which three files it changes, and why we only need to change one

    verl/workers/fsdp_workers.py            <- houses ProjZModule (the 3-layer MLP Z_φ)
    verl/workers/sharding_manager/fsdp_vllm.py  <- makes Z_φ take part in FSDP/vLLM sharding
    verl/workers/actor/dp_actor.py          <- compute_flowrl_objective, the actual loss

> **The first two files exist because of `Z_φ`.** GFlowRL's entire contribution is replacing `Z_φ` with Eq. 4's within-batch
> Monte Carlo estimate, "the auxiliary network and its optimizer state in distributed
> training are all removed". **So we only need the one place in `dp_actor.py`.**

### 1.2 One **external confirmation**: `|y|` is the sum of `response_mask`

Item 2 of `P7_DECISION.md` §5.1 is something we derived ourselves from Remark B.4:
`|y_i|` must be the number of tokens generated by the policy, not the raw response length.
FlowRL's implementation independently writes it this way:

    avg_logpf    = verl_F.masked_mean(logpf,  response_mask, axis=1)     # length normalization = count by mask
    avg_logp_ref = verl_F.masked_mean(logf_ref, response_mask, axis=1)
    ...            verl_F.masked_sum (logpf - logpf_old, response_mask, axis=1)   # the unnormalized branch

**The denominator of `masked_mean` is the number of 1s in the mask.** This is an independent corroboration of our inference,
and it also shows in passing: the normalized (`masked_mean`) and unnormalized (`masked_sum`) branches coexist in the same implementation —
matching the asymmetry of Eq. 4 unnormalized, Eq. 5/6 normalized (see the unit mismatch in `P7_STEP23_RESULTS.md` §2.5).

## 2. TBA: a same-family reference for the Eq. 4 estimator

`https://github.com/bbartoldson/TBA` · Apache-2.0 · arXiv:2503.18929

It uses **TB-VarGrad**. The GFlowRL paper's original text: the estimator "builds on the log-partition
variance loss of Zhang et al. [2023]", and "**Rather than minimize the variance** of these
targets across trajectories sharing the same condition, **we take their in-batch mean**
as a stop-gradient baseline".

> **So TBA and GFlowRL are two uses of the same quantity: VarGrad minimizes its variance, GFlowRL takes its mean.**
> TBA is the only runnable public implementation on this branch; worth reading how it computes `Ẑ(x)` and how it sets up the replay buffer.
> Downsides: its own framework (not verl), small (32★), needs porting.

## 3. f-TB / DevGrad: the most relevant paper for criterion (i) (but no code)

arXiv:2605.15417 (ICML 2026). It generalizes TB to the whole f-divergence family and proposes **DevGrad**:
no longer assuming the partition function is known, but instead **solving for an optimal within-batch constant**

    min_C  (1/B) Σ_i  L_f( Δ(y_i) + C )        such that the gradient coefficients sum to zero within the batch

> **This is exactly our `Z_t`, only with "optimize" in place of "take the arithmetic mean".**
> Criterion (i) asks "is the within-batch mean estimator still usable at `G=5`" —
> DevGrad gives another way to estimate the same constant, **the natural control group for this criterion**.
> The paper gives no code; but the formula is simple enough to implement directly in our synthetic test
> (`tools/p7/p7_fixedpoint.py` already has the framework).

## 4. Our own verl fork is already prepared

`SpaceTools-RL` @ `f0742338` · **verl 0.8.0.dev**. Checked on the ground:

    verl/trainer/ppo/core_algos.py
      POLICY_LOSS_REGISTRY / register_policy_loss / get_policy_loss_fn   already exist
      11 registered: vanilla · dppo_tv · dppo_kl · gspo · sapo · gpg ·
                    clip_cov · kl_cov · geo_mean · cispo · bypass_mode

    Signature of the registration interface (does not include the two things we need):
      policy_loss_fn(old_log_prob, log_prob, advantages, response_mask,
                     loss_agg_mode, config, rollout_is_weights)

    verl/workers/actor/dp_actor.py
      L516  select_keys = [responses, response_mask, input_ids, attention_mask,
                           position_ids, old_log_probs, advantages]
      L528  if self.config.use_kl_loss:  select_keys.append("ref_log_prob")   <- already in place
      L615  call site of policy_loss_fn(...)
      L648  ref_log_prob = model_inputs["ref_log_prob"]                        <- same scope

**So the minimal change path (four steps, about 10 lines):**

1. `actor.use_kl_loss=True` and `kl_loss_coef=0` — **`ref_log_prob` gets selected into the micro-batch,
   while the KL penalty multiplied by 0 has no effect**. GFlowRL needs the ref forward anyway, so we get it for free.
2. `select_keys.append("token_level_scores")` — one line. `advantages` is group-normalized,
   GFlowRL needs the **raw** `r`; `token_level_scores` is written into the batch at `ray_trainer.py:1528`.
3. `@register_policy_loss("gflowrl")` written in `core_algos.py`.
4. At the call site at L615, pass in `ref_log_prob` and `token_level_scores` (the signature has to be extended, or use a closure).

> **Note the already registered loss `bypass_mode`** (`core_algos.py:2236`): it sets
> `old_log_prob = rollout_log_prob`, and explicitly handles IS weights and the rejection mask.
> GFlowRL's `w_i = min(π_θ/π_old, 1+ε)` is the same kind of thing; **its implementation is worth reading once before writing our own**.

## 5. Net effect on P7

- **A′'s gap is externally confirmed**: no implementation of a GFlowNet-style objective on multi-turn tool trajectories was found.
- **"Is the loss written correctly" now has two safeguards**: the synthetic fixed-point test (done) + a line-by-line comparison against FlowRL's
  `compute_flowrl_objective` (the TB part differs from GFlowRL only in where `Z` comes from).
- **The `|y|` inference is independently corroborated** (§1.2), and can be downgraded from "pending re-check" to "confirmed".
- **Engineering effort revised down**: the change is smaller than FlowRL's (no need for `fsdp_workers.py` and `fsdp_vllm.py`),
  and both the registry and `ref_log_prob` are already in our fork.
- **Criterion (i) gains a control group**: DevGrad (f-TB).
